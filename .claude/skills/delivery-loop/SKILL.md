# /delivery-loop

Как в **этом** проекте устроена быстрая доставка историй. Полосы: `/backend-delivery` и
`/frontend-delivery`. Полный TDD-конвейер `/continue` (red→green по слоям) **не**
является режимом по умолчанию — см. «Режим доставки» ниже.

## Режим доставки (AdaptiveTutor)

```
interview → story → api-spec → test-spec (+ mockups для UI)
        → реализация по api-spec
        → тесты из test-spec (с sanity fail хотя бы раз)
        → коммит поведения + progress.md
        → /refactor → коммит рефактора
        → учёт → пуш → branch:dev
```

Между кусками: `/clear-session` → New Chat → следующий кусок (Tier 1 сценарий или экран).
Tier 1 закрыт → `/harvest` для Tier 2. Tier 3 не строится.

**Не делать:** `red-usecase` / `green-usecase` / `red-adapter` / `green-adapter` на каждый
порт; `/test-review`+`/refactor` после каждого микрошага; boundary review на каждый блок
(достаточно конца истории / перед merge).

## Роли

**Человек** держит: границы истории, порядок пуша, предметные решения, которых нет в коде
и макете. Смотрит результат и цвет прогона, не шаги внутри.

**Сессия** ведёт историю от ветки до слияния и останавливается на интервью и на готовой
истории.

Две сессии могут идти параллельно на одном дереве (бэк / фронт). Папки не пересекаются,
репозиторий общий — коммит **путями**, без голого `git add` всего индекса.

## Цикл

```
dev ──► ветка ──► интервью ──► спека ──► тест-спека ──► реализация ──► тесты
                                  │                                      │
                     (точка встречи полос)         коммит поведения ◄─────┘
                                                          │
                                          рефактор ──► прогон ──► коммит рефактора
                                                                        │
                                                       учёт ──► пуш ветки ──► branch:dev
```

Один чекпоинт на историю для человека. Внутри — куски размера Tier 1 сценария / экрана.

## Правила

### Границы истории

Связанное — одной веткой. Несвязанное — в `ProductSpecification/tasks/BACKLOG.md`, не в
текущую историю.

### Вопросы

Три-четыре пачкой, варианты + одна рекомендация. Не диалог.

### Спека — точка встречи

`ProductSpecification/api-specs/*.yaml` раньше обеих реализаций. Фронт типизирует провод
по ней; бэкенд правит YAML в том же коммите, что и отход от неё.

### Коммит — путями

```
git commit -m "..." -- backend ProductSpecification
```

Новый файл: `git add -- <файл> && git commit ... -- <пути>`.

### Ветки и пуш

- Ветка от `dev`, одна на историю. `dev` локально не выкатывать, если рядом вторая сессия.
- Слияние: `git push origin <ветка>:dev`, затем `git fetch origin dev:dev`.
- Порядок пуша — у человека (не вливать половину, пока вторая полоса пишет).

### Рефактор

После зелёного, отдельным коммитом. До зелёного рефакторить нечем.

## Прогоны

Перед пушем — локальный CI (см. `.github/workflows/README.md`):

```bash
bash scripts/ci-local.sh              # rules + backend + frontend
bash scripts/ci-local.sh --fast       # только pytest на одноразовом Postgres/Redis
bash scripts/ci-local.sh --rules
```

Точечно без скрипта (`ProductSpecification/technology.md`):

```bash
cd backend && pytest
cd frontend && npm test
pytest acceptance   # Selenium / HTTP acceptance
```

## Как читать сессию

Старт: этот файл → `/backend-delivery` или `/frontend-delivery`.  
«Что дальше» → `ProductSpecification/stories.md` + `progress.md`.  
«Почему так» → `interview.md` / `decisions/` истории.  
Конец куска → `/clear-session`.
