# /delivery-loop

Как в **этом** проекте устроена быстрая доставка историй. Полосы: `/backend-delivery` и
`/frontend-delivery`. Полный TDD-конвейер `/continue` (red→green по слоям) **не**
является режимом по умолчанию — см. «Режим доставки» ниже.

## Режим доставки (AdaptiveTutor)

```
interview → story → api-spec → test-spec (+ mockups для UI)
        → реализация по api-spec
        → тесты из test-spec (с sanity fail хотя бы раз)
        → коммит поведения + progress.md
        → /refactor → коммит рефактора
        → учёт → пуш → branch:dev
```

Между кусками (обычный режим): `/clear-session` → New Chat → следующий кусок
(Tier 1 сценарий или экран). Tier 1 закрыт → `/harvest` для Tier 2. Tier 3 не строится.

**Не делать:** `red-usecase` / `green-usecase` / `red-adapter` / `green-adapter` на каждый
порт; `/test-review`+`/refactor` после каждого микрошага; boundary review на каждый блок
(достаточно конца истории / перед merge).

## Ярлыки аргументов

| Ввод | Действие |
|------|----------|
| `/delivery-loop` | Общая рамка; «что дальше» из `stories.md` + `progress.md`; один кусок, потом `/clear-session` |
| `/delivery-loop afk` | Автономный прогон — см. «Режим afk» ниже |
| `/delivery-loop пара` | То же, что `afk` |
| `/delivery-loop 50m` | То же, что `afk` |
| `/delivery-loop batch` | То же, что `afk` |

Полоса по умолчанию — бэкенд (`/backend-delivery`). Явно: `/delivery-loop afk front`.

## Режим afk (tg-cursor / пары)

Для запуска с телефона или на перемене, когда человека нет ~45–50 минут отвечать и
делать `/clear`. Жёсткий потолок у tg-cursor — `agentTimeoutMs` (часто 60 мин); мягкий
бюджет скилла **50 минут**, чтобы уложиться с запасом и оставить отчёт.

### Когда включать

- Спека + test-spec уже есть; следующий шаг — **реализация / тесты / рефактор** по
  `progress.md`, не интервью и не открытые DECISION.
- Пользователь пишет `afk` / `пара` / `50m` / `batch` (или то же смыслом: «на пару»,
  «без clear», «крути пока меня нет»).

### Что делать

1. Зафиксировать `started_at` и бюджет **50 мин** wall-clock.
2. Прочитать `stories.md` + активный `progress.md`. Собрать очередь следующих
   **готовых к коду** кусков (Tier 1 / экран / уже принятый Tier 2 после harvest) —
   только те, где не нужны ответы человека.
3. Для каждого куска в той же сессии прогнать полосу целиком:
   реализация → тесты (sanity fail хотя бы раз) → коммит поведения + `progress.md` →
   `/refactor` → коммит рефактора → учёт в `progress.md`.
4. Между кусками **не** вызывать `/clear-session` и **не** ждать New Chat / ответа.
   Сразу брать следующий кусок из очереди, пока бюджет позволяет.
5. Перед стартом следующего куска оценить остаток: если меньше ~12–15 мин — **не**
   начинать новый кусок; дописать отчёт и остановиться.
6. В конце (бюджет / стоп-условие / очередь пуста): короткий `/handoff` (если есть что
   записать) + `git push -u origin HEAD` (как backup, без слияния в `dev`) + отчёт.

### Стоп без ожидания человека

Остановиться сразу (с отчётом), если:

- нужен ответ на интервью / DECISION / выбор архитектуры, которого нет в спеке;
- красные тесты не чинятся без предметного решения;
- следующий кусок — mockups / interview / merge-порядок с другой полосой;
- бюджет исчерпан или осталось слишком мало на целый кусок;
- история / текущий tier закрыт.

Не задавать вопросы пачкой «на потом в чат». Варианты и рекомендацию — в отчёт и при
нужде одной строкой в `progress.md` / handoff, чтобы человек разобрал на следующей
перемене.

### Отчёт в конце (обязательно)

```
AFK done (~N мин).

• Сделано: {сценарии / коммиты}
• Progress: {последний [x] / следующий [ ]}
• Push: {ветка → origin / ничего / ошибка}
• Блокер (если есть): {один абзац + варианты}
• Дальше вручную: {одна команда, напр. /delivery-loop afk или правка X}
```

После отчёта **не** продолжать работу и **не** требовать clear — человек сам решит на
перемене.

### Не делать в afk

- Интервью, открытые вопросы, ожидание ответа.
- `/clear-session` между кусками (контекст держит одна сессия агента / tg resume).
- Слияние в `dev` и «что дальше?» без кода, если очередь реализации ещё не пуста.
- Начинать кусок, который заведомо не влезет в остаток бюджета.

## Роли

**Человек** держит: границы истории, порядок пуша, предметные решения, которых нет в коде
и макете. Смотрит результат и цвет прогона, не шаги внутри.

**Сессия** ведёт историю от ветки до слияния и останавливается на интервью и на готовой
истории.

Две сессии могут идти параллельно на одном дереве (бэк / фронт). Папки не пересекаются,
репозиторий общий — коммит **путями**, без голого `git add` всего индекса.

## Цикл

```
dev ──► ветка ──► интервью ──► спека ──► тест-спека ──► реализация ──► тесты
                                  │                                      │
                     (точка встречи полос)         коммит поведения ◄─────┘
                                                          │
                                          рефактор ──► прогон ──► коммит рефактора
                                                                        │
                                                       учёт ──► пуш ветки ──► branch:dev
```

Один чекпоинт на историю для человека. Внутри — куски размера Tier 1 сценария / экрана.

## Правила

### Границы истории

Связанное — одной веткой. Несвязанное — в `ProductSpecification/tasks/BACKLOG.md`, не в
текущую историю.

### Вопросы

Три-четыре пачкой, варианты + одна рекомендация. Не диалог. В режиме `afk` вопросы
не задавать — стоп с вариантами в отчёте.

### Спека — точка встречи

`ProductSpecification/api-specs/*.yaml` раньше обеих реализаций. Фронт типизирует провод
по ней; бэкенд правит YAML в том же коммите, что и отход от неё.

### Коммит — путями

```
git commit -m "..." -- backend ProductSpecification
```

Новый файл: `git add -- <файл> && git commit ... -- <пути>`.

### Ветки и пуш

- Ветка от `dev`, одна на историю. `dev` локально не выкатывать, если рядом вторая сессия.
- Слияние: `git push origin <ветка>:dev`, затем `git fetch origin dev:dev`.
- Порядок пуша — у человека (не вливать половину, пока вторая полоса пишет).

### Рефактор

После зелёного, отдельным коммитом. До зелёного рефакторить нечем.

## Прогоны

Перед пушем — локальный CI (см. `.github/workflows/README.md`):

```bash
bash scripts/ci-local.sh              # rules + backend + frontend
bash scripts/ci-local.sh --fast       # только pytest на одноразовом Postgres/Redis
bash scripts/ci-local.sh --rules
```

Точечно без скрипта (`ProductSpecification/technology.md`):

```bash
cd backend && pytest
cd frontend && npm test
pytest acceptance   # Selenium / HTTP acceptance
```

## Как читать сессию

Старт: этот файл → `/backend-delivery` или `/frontend-delivery`.  
«Что дальше» → `ProductSpecification/stories.md` + `progress.md`.  
«Почему так» → `interview.md` / `decisions/` истории.  
Конец куска → `/clear-session` (кроме режима `afk` — там цепочка кусков и отчёт).
