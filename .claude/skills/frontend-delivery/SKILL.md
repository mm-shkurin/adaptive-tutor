# /frontend-delivery

Конвейер **фронтовой полосы** внутри истории. Рамка — `/delivery-loop`. Парная полоса —
`/backend-delivery`. Точка встречи: `ProductSpecification/api-specs/`.

## Режим (без послойного TDD)

```
интервью ──► мокап ──► контракт ──► вёрстка ──► тесты ──► рефактор ──► учёт
   (раз       (раз      (на экран)   (на экран)  (на экран) (на экран)  (на экран)
  на историю) на surface)
```

Кусок = один экран / один Tier 1 UI-сценарий. Не разворачивать
`red-selenium` → `red-frontend` → … цепочку из `/continue`, пока пользователь явно не
попросил полный TDD.

### 1. Интервью — раз на историю

`/interview`, если ещё не закрыт. Scope, отказы, намеренно не делаем.

### 2. Мокап — раз на поверхность

Авторитет дизайна: мокапы истории в
`ProductSpecification/stories/NN-…/mockups/` и/или корневой
`adaptive-tutor-mockup.html`. Пока экран не перенесён — правки в мокап; после — в
компоненты (и бэкпорт в мокап при расхождении). Обе ширины, если экран ими живёт.

Перед вёрсткой читать `.claude/guidelines/frontend-rules.md`.

### 3. Контракт — до вёрстки

Типы/клиент по `ProductSpecification/api-specs/*.yaml`, не по «тому, что сервер отдаёт
сегодня». Живёт в `frontend/src/shared/api/` (`backend/paths.js`, клиенты).

- Имена полей с провода не переименовывать.
- Чего нет в спеке — не рисовать как факт; недостающее помечать комментарием с причиной.

### 4. Вёрстка — из мокапа

Компоненты повторяют мокап. Переводчик провод→вид — одно место на экран, если нужен.

### 5. Тесты из test-spec

Два слоя по возможности:

- **Чистый:** vitest (`cd frontend && npm test`) — логика, переводчики, развилки.
- **Браузерный:** Selenium acceptance (`pytest acceptance`) — один критичный сценарий на
  экран, когда стек поднят. Не обязателен на каждый микрокоммит; обязателен перед
  закрытием UI Tier 1 сценария.

Порядок: написать/включить тест → хотя бы раз увидеть fail → зелёный.

### 6. Рефактор — после зелёного

`/refactor`, отдельный коммит. Затем прогон `npm test` ещё раз.

### 7. Учёт

`progress.md` + `stories.md`. Вне scope → `ProductSpecification/tasks/BACKLOG.md`.
Коммит путями: `git commit -m "..." -- frontend ProductSpecification`.

## Стык с бэкендом

| Артефакт | Кто | Смысл |
|---|---|---|
| `ProductSpecification/api-specs/*.yaml` | до реализации | контракт истины |
| `frontend/src/shared/api/` | фронт | клиент по спеке |
| расхождения | обе полосы | назвать в чате / backlog, не чинить молча только у себя |

1. Спека раньше обеих реализаций — фронт не ждёт сервер.
2. Заход: сверка `stories.md` + недавний `git log -- backend/`.
3. Сценарий без ручки сервера — `it.skip` / skip с причиной, не удалять молча.
