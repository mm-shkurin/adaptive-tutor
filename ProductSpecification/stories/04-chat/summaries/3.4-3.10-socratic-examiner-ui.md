## tests acceptance Selenium 3.4–3.10 (2026-11-19)

**Surprise:** `isLineBody` rejected `kind: "reply"`, so tell/try releases never entered the thread even when the API succeeded.
**Why:** the guard only listed examiner kinds after the UI wiring pass.
**Impact:** any send that returns a grounded/release line must keep `reply` in the line guard.

## implementation mergeLines (2026-11-19)

**Surprise:** a second click on an already-graded choice appended a second identical grade row in the UI.
**Why:** `persist=False` re-emits the prior grade id; naive `lines.concat(result.lines)` duplicates it.
**Impact:** chat send updates must merge incoming lines by id, not only append.

## Decision (2026-11-19)

**Decision:** when no examiner question is open, still render choices on the last graded question.
**Why:** UI 3.10 needs a second click target after the series stops; the API returns the prior grade unchanged.
**Where applied:** `activeExaminerQuestion` in `frontend/src/features/chat/logic/chatView.js`
