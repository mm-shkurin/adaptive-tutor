## design (2026-11-09)

**Decision:** `IndexDocuments._index` returns immediately when `status` is `ready` or `failed`; a forced second run still calls `_index` so that guard is what refuses rework.
**Why:** Finished documents are terminal — re-running with restored bytes must not rewrite pieces or flip a failed row to ready.
**Where applied:** `backend/usecase/document/index_documents.py`, `acceptance/support/acceptance_server.py` (`_second_indexing_run`)

## green-usecase (2026-11-09)

**Quirk:** Clearing `_fail_table_after_text` and counting `FakePdfReader.read_count` are required for a real sanity fail.
**Where:** `backend/usecase/tests/statements/document_statements.py`
**Implication:** Without those, a second run still ends ready/failed with the same pieces (`_store` skips; table arm still refuses).

## green-acceptance (2026-11-09)

**Surprise:** Unskipping was already green once `_second_indexing_run` always called `_index` (empty bytes when the file was deleted).
**Why:** The finished-status guard already lived in `IndexDocuments`; the old harness early-return never exercised it.
**Impact:** Slice is usecase coverage + harness path + enabling acceptance, not a new indexing algorithm.
