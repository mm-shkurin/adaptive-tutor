## design (2026-11-09)

**Decision:** `Document.is_ready()` is true only for `status == "ready"`; `SearchDocuments` gates pieces and extracted text on that method.
**Why:** An unknown/corrupted status must not look searchable even when piece rows were forced in.
**Where applied:** `backend/domain/document/document.py`, `backend/usecase/document/search_documents.py`

## green-usecase (2026-11-09)

**Quirk:** Sanity fail required dropping the ready gate (`document is not None` alone) — the status check was already present as a string compare.
**Where:** `backend/usecase/tests/document/test_unknown_status_is_not_treated_as_ready.py`
**Implication:** Moving the check onto `is_ready()` keeps the rule on the document, not as a string literal in search.

## green-acceptance (2026-11-09)

**Surprise:** Unskipping was already green — `SearchDocuments._ready` already refused non-ready statuses.
**Impact:** Slice is domain ownership of ready + usecase coverage + enabling the acceptance scenario.
